# 🔍 Upscaly：無損失志向の画像拡大ツール（무손실 지향 확대기） `v1.2.2`

無損失を目指す画像拡大ツールです。ファイル1つ（`upscaler.html`）で動作し、すべての計算をブラウザの中で行います。
インストールするものも、アップロードする先もありません。画像が端末の外に出ることはありません。

現在のバージョンは **v1.2.2** です。変更点は [12. 変更履歴](#12-変更履歴) にあります。開発用ソース・テスト・研究資料は [Upscaly-dev](https://github.com/Velvitty/Upscaly-dev) リポジトリにあります。

## 1. かんたんな紹介

### このツールは何ですか

小さな画像を大きく引き伸ばすと、ふつうはぼやけたり、階段状のギザギザが出たり、輪郭のまわりに白い縁取りができたりします。Upscaly は写真・イラスト・漫画・文書・ロゴ・ピクセルアートのように種類の異なる画像を、それぞれに適した方法で拡大し、こうした欠点を減らしながら元の画像が持っていた情報をできるだけ守ります。

「無損失を目指す」とは、拡大した画像をもう一度元のサイズに縮小したときに原画像と同じになるように合わせて復元する、という意味です。拡大によって原画像になかった絵を作り出すのではなく、原画像が持つ情報をもっとももっともらしく広げることに集中します。輪郭強調や階段除去のようにその上に重ねる補正は、この復元をもとに見た目を整える段階なので、有効にすると結果は原画像の情報から少し離れます（[2.1](#21-拡大は情報を生み出さない)）。

### ここが便利です

- **インストール不要です。** ファイル1つをブラウザで開けば終わりです。インターネット接続も要りません。
- **画像が外に出ません。** サーバーも外部ライブラリも使いません。
- **自動で合わせてくれます。** 「自動」（자동）ボタンが画像の種類を9種類の中から見分け、その画像で直接測定して設定を決めます。
- **大きく拡大しても耐えられます。** 画像をタイルに分けて計算し、タイルの行ごとに圧縮してつなぎ合わせるので、結果が数億画素になっても、圧縮していない結果全体をメモリに載せることはありません。ただし圧縮済みの PNG ファイルは、保存が終わるまでメモリにたまります。
- **帯のないグラデーション。** 8ビットで保存するときに細かなディザを混ぜ、大きく拡大した空やグラデーションに階段のような帯が出ないようにします。16ビット PNG でも保存できます。
- **スマートフォン写真の色をそのまま。** iPhone などの Display P3 写真は P3 として読み込み P3 として保存するので、鮮やかな赤や緑がくすみません。
- **質感復元（任意）。** 大きく拡大して蝋のようにつるつるになった肌や布に、細かな質感を再び載せることができます。既定では無効です。
- **透明な画像もきれいです。** 半透明の縁に色がにじみません。
- **正確さと体感、二つの目標。** 既定の「精度」(정확도)は原画像にもっとも近く拡大します。「体感」(체감)を選ぶと、輪郭をより急に、埋もれた明暗を浮き立たせて、目により鮮明に見せます。白い縁取り（ハロー）は生じません。

### 使い方

1. `upscaler.html` を最新のブラウザで開きます。
2. **画像を開く**（이미지 열기） を押すか、画像を画面にドラッグ＆ドロップするか、貼り付けます。一度に20枚まで、JPEG・PNG・WebP・AVIF を開けます。
3. **倍率**（배율） を選びます。縦横の長さ基準（1〜12×）と画素数（面積）基準があり、「自動」を選ぶと、この端末で最後まで処理できる最大の倍率（3〜8×）を選びます。
4. **「自動: (推奨、おすすめ)」（자동: (권장, 추천)）** を押します。画像の種類と状態を測定して下の設定をすべて埋め、何を根拠に決めたかを短く書いてくれます。原画像への忠実さより目に鮮明であることが大事なら、**目標**（목표）で「体感」を選びます。
5. **拡大実行**（확대 실행） を押します。**原画像と比較**（원본 비교）が有効なら、画面の左半分に原画像をブラウザで拡大したもの、右半分に結果が表示されます。画面をドラッグして移動し、ホイールで拡大し、**フィット**（맞춤、F キー）、**1:1**、**原画像と比較**（C キー）ボタンを使います。
6. **PNG 保存**（PNG 저장） で現在の画像を、**すべて保存**（모두 저장） で処理した画像をまとめて保存します。

### 設定を自分で選ぶとき

画面右側の欄は処理の順に並んでいます。

| 欄 | 役割 |
|---|---|
| 倍率（배율） | 何倍に拡大するか。1× は拡大せず整えるだけ |
| プリセット · 自動（프리셋 · 자동） | 33種類のプリセットまたは「自動」 |
| 目標（목표） | 「精度」（原画像にもっとも近く、既定）または「体感」（輪郭の傾きと局所コントラストを上げて目により鮮明に、強さ 25〜150%）。プリセットと「自動」は変えません |
| 再構成カーネル（재구성 커널） | 新しい画素をどう埋めるか（DCCI・ピクセルアート・Lanczos・Catmull-Rom・Mitchell・最近傍）、段階拡大、リンギング遮断、原画像整合 |
| ノイズ・ゴミ除去（노이즈·잡티 정리） | ノイズと JPEG の痕跡を拡大前に取り除く |
| 鮮明度復元（선명도 복원） | 撮影・スキャン時に生じたぼけを拡大前に戻す |
| 階段除去（계단 제거） | 輪郭の方向にだけ平均して階段をなくす、輪郭再描画、JPEG ブロック緩和 |
| 輪郭強調（윤곽 강조） | ハローを抑えたアンシャープマスク |
| 質感復元（질감 되살리기） | 原画像になかった細かな質感を載せる。既定は無効、写真・絵画に20〜30%を推奨 |
| 色処理（색 처리） | ホワイトバランス（プリセットと自動が触らない別機能）、線形光での計算、8ビットディザリング、16ビット保存 |

チェックとスライダーは選んだとおりに動作します。たとえば「段階に分けて拡大」（단계로 나눠 확대）は、有効にすると測定上悪くなる場合でも分けて拡大します。その代わり、隣の表示灯が現在の画像で測定した結果を知らせます。画像を開いた直後は、このチェックの初期値を画像から測定して決めますが、その測定が終わる前にチェックを変えたり「自動」を押したりすると、遅れて終わった測定はその選択に手を出しません。

### 知っておくとよいこと

- すでに何度も縮小して保存し直した画像は、元々あった細部が失われているので取り戻せません。Upscaly は残っている情報をもっとももっともらしく広げるだけで、存在しない顔や文字を作り出すことはしません。
- ベクター原本（SVG、AI）があるロゴや図面は、その原本を使うほうが常に良い結果になります。
- 8× で拡大すると結果が数百メガ画素になり、時間がかかります。進捗表示に残り時間が出ます。

## 2. 原理

### 2.1 拡大は情報を生み出さない

デジタル画像は、連続した場面を一定の間隔で写し取った標本です。標本間隔より細かい模様は、最初から記録されていません。そのため拡大の本質は「標本の間をどう埋めるか」であり、埋め方によってぼけ・階段・リンギングのような欠点が生じます。

Upscaly は埋め方を選ぶときに3つの原則を置いています。前の2つは復元段階（補間 → セル範囲 → 整合）の制約で、対応するチェック（「リンギング・ハロー遮断」（링잉·후광 차단）、「原画像整合補正」（원본 정합 보정））を有効にしたときに成り立ちます。

1. **新しい極値を作らない。** 復元された画素は、自身が属する原画像の 2×2 マスの最も暗い値と最も明るい値の間にあります（セル範囲制限）。リンギングとハローは原画像になかった極値なので、この段階では生じません。
2. **縮小し直せば原画像になる。** 復元した画像を光の面積平均で縮小し直すと原画像と同じになるように合わせます（原画像整合補正）。原画像の情報と矛盾しないという意味です。
3. **輪郭は方向に沿って埋める。** 輪郭を横切る方向に混ぜると輪郭がぼけ、軸に沿って混ぜると階段が生じます。輪郭が伸びる方向を読み取り、その方向にだけ埋めます（DCCI）。

2つの制約（1・2）は同時に満たすのが難しく、一方を満たすともう一方が少しずれます。そこで両者を交互に満たす交互投影を使います（[4.6](#46-交互投影)）。

復元後のアンシャープ、方向平滑化、輪郭再描画、質感復元は見た目を整える段階なので、この2つの制約を改めて守ることはしません。そのため、これらを有効にした最終結果は原画像のマスの範囲を少し超えたり、縮小し直したときに原画像と少し異なったりすることがあります。画面の「拡大整合誤差」は、この補正を行う前の値で測定します。「最小介入 · 純粋 Lanczos」（최소 개입 · 순수 Lanczos）のようなプリセットは、2つの制約をどちらも無効にします。

### 2.2 光は線形光で混ざる

画面用に保存された値（sRGB）は、人の目に合わせて曲げてある値です。2つの画素の光を混ぜるのは、この曲げられた値ではなく実際の光の量（線形光）で行うのが正しいやり方です。曲げられた値のまま補間すると、明るい面と暗い面の境界が暗く固まります。Upscaly は既定で計算を線形光で行い、保存するときだけ sRGB に戻します。「線形光で計算」（선형광에서 계산）のチェックを外すと、ガンマ空間で直接計算します（推奨しません）。

透明な画像は、色にアルファを掛けておいた値（乗算済み）で計算します。そして原画像の準備、段階拡大の中間段階、最終的なタイル計算のすべてで、**アルファも色とまったく同じ演算を通ります。** 色とアルファが異なるフィルタを通ると、後で色をアルファで割るときに半透明の縁の色が狂うためです。

### 2.3 ぼけとノイズは拡大前に、原画像の解像度で扱う

カメラのレンズやスキャナーは場面を少しぼかして写し、センサーと圧縮はノイズを加えます。これらの欠点は原画像の解像度で生じたものなので、原画像の解像度で戻すのが正しいやり方です。拡大後に扱うと欠点まで一緒に大きくなっているため、より難しく、遅くなります。

- **ぼけ** は Richardson–Lucy デコンボリューションで逆推定します。拡大結果が原画像よりくっきり見える理由の大部分はここから来ます。
- **ノイズ** は画像から直接測ったノイズスペクトルを基準に取り除きます。ノイズより大きい成分（輪郭・質感）は残し、ノイズと区別できない成分だけを減らします。
- **JPEG の痕跡** はファイルの量子化テーブルを読んで取り除きます。このとき輝度の DCT 係数は元のファイルの量子化区間の外に出ないように戻すので、ファイルに記録された細部を消しません。この保証はこの投影段階の輝度にだけ当てはまります。色成分と、その後のブロック緩和・ノイズ除去・デコンボリューション・拡大・鮮鋭化は、係数を区間の外へ動かすことがあります。

### 2.4 線は描き直す

2色がすっぱり分かれるグラフィック（ロゴ・線画・文字）では、原画像の階段そのものが「正解」のように保存されがちです。Upscaly はこうした境界を見つけ、拡大解像度で1画素幅の輪郭として描き直します。滑らかな補間値の50%等値線を輪郭の位置とみなし、その距離に応じて断面を立てます（符号付き距離方式）。方向平滑化が輪郭の形をまっすぐに伸ばし、再描画が断面を立てるので、両方を併用すると階段がなく滑らかで、にじまない線になります。

### 2.5 作り出した質感は質感ではなくグレインである

拡大は、原画像の画素間隔より細かい模様を作れません。そのため大きく拡大した写真の肌のきめ、布の織り目、葉脈が消え、蝋のようにつるつるに見えます。消えた質感の **量** は推測できます。自然画像では空間周波数が2倍になるごとに含まれるエネルギーがほぼ同じだからです（パワースペクトルがおおよそ $`1/f^2`$）。原画像の細かい帯域で測った質感の強さから、失われたオクターブにどれだけの質感があったかを見積もれます。

しかし質感の **位置と形** は原画像にありません。Upscaly が載せるのは、その量に合わせたノイズ、つまりフィルムグレインのような細かな質感です。正解と位置が合わないので、エネルギーを正解並みに満たすほど原画像との差（PSNR）は大きくなり、目にも質感というよりノイズのように見え始めます。そのため質感復元は「自動」が触らない任意の機能で、弱い強度で人物・肌・布のような滑らかな面に使うよう案内しています。質感の形までもっともらしく描くには生成モデル（ニューラルネットワーク）が必要です（[11. 限界](#11-限界)）。

### 2.6 8ビットの階段は細かなノイズで隠す

処理は浮動小数点で行いますが、ふつう保存する8ビット PNG は明るさを256段階でしか記録しません。滑らかな空を8倍に拡大すると、原画像では数画素ごとに1段階ずつ変わっていた明るさが、数十画素幅の帯になります。丸める直前に半段階より小さいノイズを混ぜると（ディザリング）、帯の境界が細かな質感に散って目に見えなくなります。ノイズは画面座標だけで決まる模様なのでタイルごとに同じで、3チャンネルに同じものを使うので灰色は灰色のまま残ります。単色面のようにすでに正確に割り切れている値は変わりません。

### 2.7 スマートフォン写真の色は sRGB より広い

最近のスマートフォン写真は、sRGB より広い Display P3 色域で撮影されることが多くなっています。ふつうのキャンバス（sRGB）で読み込むと、ブラウザが sRGB の外にある鮮やかな赤・緑を sRGB の内側へ押し込むため、拡大結果が原画像よりくすみます。Upscaly は元ファイルの色プロファイルを読み、広い色域であれば P3 キャンバスで読み込み、結果にも P3 プロファイルを付けて保存します。Display P3 は sRGB と同じ伝達曲線を使うので線形光の計算はそのままで、原色だけが異なります。

### 2.8 画像ごとに答えが違う

写真に合う設定は線画を台無しにし、線画に合う設定は写真を台無しにします。原画像整合は写真では有効ですが、2色がはっきり分かれる線画では原画像の階段を正解として復元してしまいます。そこで「自動」はまず画像の種類を見分け（9種分類器）、種類に合うプリセットから出発して、その画像で測った値で細部を調整します。大きく拡大するときは、1兆5,200億通りの設定空間を探索して見つけた値を使います（[9.4](#94-拡大復元の探索)）。

### 2.9 正確さと体感は別の目標

原画像にもっとも近い結果（PSNR がもっとも高い結果）が、目にもっとも鮮明に見える結果とは限りません。拡大は、原画像の解像度で表せる輪郭さえ少し鈍らせ（正解に対する輪郭の傾き 0.81 倍）、原画像数画素の大きさの明暗差も弱めます（0.94 倍）。目はこの二つを鮮明さとして感じます。そこで目標を二つに分けました。「精度」はこれまでどおりの復元で、「体感」はその上でこの二つを正解の水準まで戻します。新しい極値を作らないので白い縁取りは生じず、原画像になかった質感を描き込むこともありません。その代わり、原画像との数値は少し下がります（[4.21](#421-体感シャープネス)、[9.10](#910-体感シャープネス)）。

## 3. 動作の仕組み

### 3.1 全体の流れ

```
ファイル ─▶ デコード(EXIF の向き) ─▶ 色プロファイル(広色域なら P3 キャンバス) ─▶ JPEG ヘッダー(量子化テーブル・サンプリング) ─▶ 被写体ボックス
                                              │
              「自動」: 分析画像 ─▶ 9種分類 ─▶ プリセット + 測定による調整 ─▶ 拡大復元の探索値 / 方向平滑化の測定 / 段階拡大の測定
                                              │
原画像の準備(原画像解像度) : 線形光プレーン(乗算済み) ─▶ 色処理 ─▶ DCT 精密復元 ─▶ ブロック緩和 ─▶ ノイズ除去 ─▶ RL デコンボリューション ─▶ 段階拡大の中間段階
                                              │
タイル計算(ワーカープール)   : 補間 ─▶ セル範囲 ─▶ 整合↔セル範囲の交互投影 ─▶ 統計 ─▶ アンシャープ ─▶ 方向平滑化 ─▶ 輪郭再描画 ─▶ (質感) ─▶ 乗算解除 ─▶ エンコード(8ビットディザ)
                                              │
                         タイルキャッシュ(LRU) ─▶ 画面 / タイル行単位の PNG 保存(8・16ビット、sRGB または P3)
```

### 3.2 読み込み

ファイルはまず `createImageBitmap`（EXIF の向きを適用）でデコードし、うまくいかなければ `<img>` の Blob URL、次に Data URL の順に切り替えます。広色域ファイル（2.7節）はデコード前に判別して `<img>` 経路（Blob URL、だめなら Data URL）を先に使い、どちらも失敗したときだけ `createImageBitmap` に切り替えます。`createImageBitmap` の既定の色変換はブラウザごとに異なり、sRGB に切り詰めてしまうことがあるためです。大きなファイルではブラウザが実際に数十秒かかることもあるので、制限時間はファイルサイズに比例して設定します（45秒 + 1 MB あたり9秒、最大5分）。どの経路でも、待機が終わらないまま残ることはありません。

JPEG であればヘッダーだけを読み、量子化テーブル、サンプリング比（4:2:0 など）、品質の推定値、EXIF の向きを得ます。エントロピー符号化データは復号しません。デコーダーが EXIF の向きを適用したかどうかはデコード結果の幅・高さで確認し、JPEG の 8×8 格子を表示方向に合わせて揃え直します。

ファイルから色プロファイルも探します（セグメント・チャンク・ボックスのヘッダーをたどりながら必要な箇所だけ読むので、前に大きなメタデータや映像ボックスがあっても見つけられます）。JPEG は APP2 の `ICC_PROFILE` セグメント、PNG は cICP・iCCP・sRGB チャンク（順序に関係なくこの優先順位）、WebP は ICCP チャンク、AVIF・HEIF は主画像に関連付けられた colr ボックスです。sRGB より広い色域であれば原画像のキャンバスを `display-p3` で作ってその上に描き、情報行に「Display P3」と表示します。ブラウザが P3 キャンバスに対応していなければ、従来どおり sRGB で読み込みます。

画像ごとに原画像を360px程度に縮小して顕著性（平均色からの距離）の塊を探し、被写体ボックスを作ります。画面の「被写体」（피사체）ボタンで確認できます。

### 3.3 原画像の準備（`prepareSource`）

原画像の解像度で完結する補正をすべてここで行います。結果は設定のキーとともに直近2つまでキャッシュされ、拡大結果がキャッシュから押し出されても、同じ設定であれば再利用されます。

1. **線形光プレーン。** 8ビット sRGB を256要素の表で線形光に変換し、アルファがあれば色にアルファを掛けます。
2. **色処理。** ホワイトバランスの強さが0でないときだけ（既定は0）。
3. **DCT 精密復元。** ノイズスペクトルと JPEG 量子化テーブルで原画像を整えます。帯に分けてワーカーに任せ、DCT 格子をグローバル座標に固定しているので、帯の境界に継ぎ目ができません。
4. **JPEG ブロック緩和。** 8の倍数の位置の段差が周囲の変化より小さいときだけ平らにします。
5. **ノイズ除去。** 明るさが近い近傍どうしだけで平均します（バイラテラルフィルタ）。アルファも同じ重みで平均します。
6. **RL デコンボリューション。** アルファも同じ回数だけ通します。
7. **段階拡大の中間段階。** 大きな倍率を2つ以上に分ける場合、最終段階の手前まではここで拡大します。DCCI は中間段階でも方向補間を使い、ピクセルアートは段階ごとに輪郭を復元します。アルファは色と同じ方向の重み・セル範囲・段階間の鮮鋭化を通ります。最終段階のセル範囲・整合の基準は、中間画像ではなく **原画像** です。

### 3.4 タイル計算（`renderTile`）

結果はタイル（倍率に応じて512〜1024px、整数倍率なら倍率の倍数）に分けて計算します。各タイルは必要な分だけの原画像の断片（補間のサポート範囲 + 整合の余白 + 方向場・輪郭モデルの余白）を受け取って独立に計算するので、どのタイルを先に計算しても結果は同じです。

1. **補間。** DCCI であれば全チャンネルを一度に拡大します（`dcciStageMulti`）。方向の重みはガイドプレーン（ガンマ輝度 + アルファ輪郭項）で一度だけ計算し、チャンネル間で共有します。その後 Catmull-Rom で正確な倍率に合わせます。
2. **セル範囲制限。** 原画像の 2×2 マスのチャンネルごとの最小値・最大値でクリップします。
3. **整合補正とセル範囲の交互投影。** 2回交互に投影します（セル範囲が無効なら整合を1回）。各パスは結果領域より7画素広い領域で解くので、どのパスも係数格子の外を読みません。
4. **統計。** 結果を縮小し直したときの原画像との差（拡大整合誤差）を画面に表示するために、補正前の値で測定します。
5. **アンシャープ。** 局所振幅に比例したニーリミッターでハローを抑えます。
6. **方向平滑化。** 原画像の構造テンソルで求めた接線方向にだけ平均します。
7. **輪郭再描画。** 符号付き距離で1画素幅の輪郭を描き直します。
8. **体感シャープネス。** 目標が「体感」のときだけ、輝度で輪郭の傾きと局所コントラストを上げます。周囲の明るさの範囲は超えません（[4.21](#421-体感シャープネス)）。
9. **質感復元。** 有効にしたときだけ、原画像で測った質感の強さの分だけ、結果に欠けている細かな質感を載せます。段階拡大の場合は中間画像ではなく原画像で測定します。原画像をそのまま複製する最近傍と、パレットを守るピクセルアートのカーネルでは使わず、スライダーも無効になります。
10. **乗算解除とエンコード。** 画面用の8ビット、保存用の8・16ビットに変換します。8ビットはディザリングを有効にしておくと（既定）、丸める直前に座標で決まる細かなノイズを混ぜます。画面と8ビット保存が同じタイルを使うので、見えているとおりに保存されます。

ワーカープールはコア数 − 1個（最大8個）を起動し、5秒以内に応答がなければメインスレッドで同じエンジンを使って計算します。エンジン（`ENGINE_FACTORY`）は純粋な計算関数の集まりなので、同じコードを Blob URL のワーカーにも載せます。

### 3.5 段階拡大

大きな倍率を何回かに分けて拡大する方式です。2倍を先に、大きい倍率を先に、バランス（小さい方・大きい方を先に）、均等（√×√）、3段階の中から選びます。段階の間に鮮鋭化をかけることもできます。表示灯は、現在の画像の中央を目標倍率の分だけ光の面積平均で縮小してから、一度に拡大したものと現在の方式で段階拡大したものを原画像と比較し（PSNR）、現在のチェック状態のほうが良いかどうかを知らせます。結果は画像・設定ごとに記憶されます。

### 3.6 自動

1. **分析。** 長辺が1024を超える場合は 2×2 平均で半分ずつ、その後は整数倍のボックス平均で512以下に縮小した分析画像で、27種類の特徴を測定します。構造テンソル（質感の比率、軸に揃ったエッジ）、強いエッジと輪郭線、文字行の周期、長い直線、色・明るさの構成、原画像解像度の断片の 8×8 ブロック平面残差、最近傍拡大の格子、原画像の色数、スクリーントーンなどです。
2. **分類。** 多項ロジスティック回帰で、写真・イラスト・絵画・漫画・線画・文書・UI・ロゴ・ピクセルアートのいずれかを選びます。ピクセルアートは確率ではなく構造（最近傍の整数倍格子、または 1× での少ないパレット）で確定します。判定を後押しした根拠（1位と2位のロジット差に対する特徴ごとの寄与）を画面に表示します。
3. **プリセットと測定による調整。** 種類に合うプリセットから出発し、ノイズ（平坦面のラプラシアンの中央値）、エッジ幅、8px 格子のコントラスト、JPEG 品質から、デコンボリューションの反復回数・σ、JPEG 復元、ブロック緩和などを調整します。
4. **拡大復元の探索値。** 種類と倍率が検証条件に合えば、探索で見つけた設定をそのまま使います（`AUTO_BIG`）。写真・線画・UI・絵画は 2× 以上、文書は 4× 以上です。ロゴと漫画は 2× 以上で、かつ JPEG ファイルのときだけ使います。きれいな入力では検証を通過しなかったためです（[9.4](#94-拡大復元の探索)）。イラストには使いません。
5. **画像ごとの測定。** 探索値を使わない場合、画像（写真・ピクセルアートを除く）は方向平滑化の強さをその画像で測って選び（`autoAA`）、次に段階拡大のすべての方式を測って最も良いものに合わせます（`autoStage`）。

自動の要求には番号が付くので、遅れて終わった前の測定が新しく開いた画像に適用されることはありません。自動の後で倍率を変えると、もう一度押すよう案内します。

### 3.7 倍率自動

3〜8× のうち、レンダリングが **保証される** 最大の倍率を選びます。倍率欄の「自動」を押すと、その場で今の設定で保証される最大の倍率に移ります。保証とは、処理の全過程の最大メモリがメモリ予算の80%以内で、残りの分が最小キャッシュより大きく、結果が保存上限以内であるという意味です。保存中にメモリにたまる圧縮 PNG（データ47枚で測った最大圧縮率に余裕10%）と、キャッシュに残っている前の画像の準備済み原画像も数に入れます。倍率ごとに「自動」が選ぶ設定（プリセット・拡大復元の探索値・段階拡大）が異なり予算も変わるので、「自動」は大きい倍率から順にその倍率の設定を実際に適用してみて、最初に保証された倍率を選びます。段階拡大をこの写真で測って決めるときも、保証内に収まる方式だけを選びます。選んだら、タイルキャッシュの上限を実際にその値まで下げます。3× でも保証されない場合は、それより小さい倍率のうち保証される最大のものに切り替えます。

### 3.8 保存

ブラウザが `CompressionStream('deflate')` に対応していれば、タイル行（16ビットは128行の帯）ごとに圧縮して PNG の断片をつなぎ合わせます。8ビットはキャッシュにあるタイルを再利用し、16ビットは帯ごとに再計算します。結果全体を収める大きなキャンバスは作りませんが、圧縮した断片は保存が終わるまでメモリにためてから1つのファイルとして書き出します。ファイルには色空間チャンクと、カーネルと倍率を記した `Software` iTXt チャンク（UTF-8）が入ります。色空間チャンクはふつう sRGB で、P3 で読み込んだ画像では cICP（原色 12 = Display P3、伝達 13 = sRGB 曲線）と、同じ意味の Display P3 ICC プロファイル（iCCP）です。cICP を読めるプログラムはそれを、読めないプログラムは ICC を使います。ストリーミング圧縮のないブラウザは8ビットしか保存できません。結果を1枚のキャンバスに集めてブラウザのエンコーダーで保存し、キャンバスの限界を超えた場合はその端末の実際の限界を学習しておきます。こうしたブラウザで16ビット保存を選ぶと、保存は失敗します。

### 3.9 色処理

色処理は拡大とは分離した別機能で、既定値は0です。「色自動」（색 자동）を押すと、照明の色を3つの方法（平均、エッジ、明るい面）で推定し、3つすべてが認める分だけホワイトバランスの強さを決めます。本当の照明の色かぶりは明るい面まで染めるので3つが一緒に大きくなりますが、茶トラの猫や夕焼けのような被写体固有の色は平均だけを引っ張るからです。イラスト・絵画・UI・ロゴ・ピクセルアートの色は意図された色とみなし、補正しません。全体の明るさは維持され、チャンネルのゲインは0.55〜1.8に制限されます。

## 4. アルゴリズムと数式

以下では、$`I`$ は原画像（線形光、乗算済み）、$`U`$ は結果、$`s_x, s_y`$ は横・縦の倍率です。

### 4.1 色空間

```math
\mathrm{lin}(u) =
\begin{cases}
u / 12.92 & u \le 0.04045 \\[2pt]
\left(\dfrac{u + 0.055}{1.055}\right)^{2.4} & \text{それ以外}
\end{cases}
\qquad
\mathrm{srgb}(v) =
\begin{cases}
12.92\,v & v \le 0.0031308 \\[2pt]
1.055\,v^{1/2.4} - 0.055 & \text{それ以外}
\end{cases}
```

8ビット → 線形光には256要素の表を、線形光 → 8ビットには8,192要素の表（量子化誤差1段階未満）を使います。16ビットのエンコーダーは $`\sqrt{v}`$ 軸で表を作り、黒付近の急な区間でも1段階以内に収めます。8ビットの256段階を線形光に変換してから戻すと、256段階すべてがそのまま保たれます（[9.1](#91-不変条件)）。

アルファがある場合、計算は乗算済みの値 $`(\alpha R, \alpha G, \alpha B, \alpha)`$ で行い、エンコードの直前に $`\alpha > 10^{-7}`$ であれば $`\alpha`$ で割ります。

### 4.2 再構成カーネル

分離型（横 → 縦）で適用し、画素中心を揃えます（$`u = (X + 0.5)/s - 0.5`$）。縮小のときはカーネルを倍率の分だけ広げてエイリアシングを防ぎます。

```math
L_a(x) = \mathrm{sinc}(x)\,\mathrm{sinc}(x/a)\ \ (|x| < a),\qquad
k_{B,C}(x) = \tfrac16
\begin{cases}
(12 - 9B - 6C)|x|^3 + (-18 + 12B + 6C)|x|^2 + (6 - 2B) & |x| < 1 \\
(-B - 6C)|x|^3 + (6B + 30C)|x|^2 + (-12B - 48C)|x| + (8B + 24C) & 1 \le |x| < 2
\end{cases}
```

Lanczos-3・4 は $`a = 3, 4`$、Catmull-Rom は $`(B, C) = (0, 0.5)`$、Mitchell–Netravali は $`(1/3, 1/3)`$ です。最近傍は整数倍率で原画像をそのまま複製するので、縮小し直すと原画像とビット単位で一致します。

### 4.3 エッジ適応 DCCI

Zhou ら（2012）の方向性3次畳み込み補間をもとに、1段階ごとに2倍ずつ拡大します（角揃え: 出力 $`(2i, 2j)`$ = 入力 $`(i, j)`$）。

**第1段階: 2×2 マスの中央。** 4×4 の近傍で2つの対角方向の変化量を測ります。$`G`$ はガイドプレーン（ガンマ輝度 0〜255）、$`n_{\mathrm{off}}`$ はノイズフロアです。

```math
d_1 = \sum_{(p,q) \in \nearrow} |G_p - G_q| + n_{\mathrm{off}},\qquad
d_2 = \sum_{(p,q) \in \searrow} |G_p - G_q| + n_{\mathrm{off}}
```

それぞれの和は、その対角方向に隣り合う9組です。重みは次のとおりです（$`T = 1.15`$）。

```math
(w_a, w_b) =
\begin{cases}
(0, 1) & 1 + d_1 > T(1 + d_2) \\
(1, 0) & 1 + d_2 > T(1 + d_1) \\
\left(\dfrac{a}{a+b}, \dfrac{b}{a+b}\right),\ a = \dfrac{1}{1 + d_1^{5}},\ b = \dfrac{1}{1 + d_2^{5}} & \text{それ以外}
\end{cases}
```

$`\nearrow`$ の変化が大きければ輪郭は $`\searrow`$ 方向に伸びているので、その方向に補間します。各方向の値は3次畳み込みのタップ $`(-1, 9, 9, -1)/16`$ です。

```math
p_a = \tfrac{1}{16}\big(9(f_{12} + f_{21}) - (f_{03} + f_{30})\big),\quad
p_b = \tfrac{1}{16}\big(9(f_{11} + f_{22}) - (f_{00} + f_{33})\big),\quad
v = \mathrm{clip}\big(w_a p_a + w_b p_b,\ \min_4 f,\ \max_4 f\big)
```

最後の `clip` は原論文にない追加です。新しい値が最も近い近傍4点の範囲を超えないようにするので、この段階からリンギングとハローが生じません。

**第2段階: 横・縦の間の画素。** 45°回転した格子で、同じ手順を横・縦方向に行います。境界は鏡映で折り返して偶対称性を保ちます。

**段階数。** 倍率ごとに実測して固定した表（`EDI_PLAN`）を使います。2× 以下は2倍格子の1段階、それより大きければ4倍格子（2段階）まで拡大した後、Catmull-Rom で正確な倍率に合わせます（[8. 最適化](#8-最適化)）。

### 4.4 セル範囲制限

出力標本 $`U(X, Y)`$ が属する原画像のマス $`(i..i{+}1,\ j..j{+}1)`$ のチャンネルごとの範囲でクリップします。

```math
U(X, Y) \leftarrow \mathrm{clip}\Big(U(X, Y),\ \min_{(p,q) \in \mathrm{cell}} I_{p,q},\ \max_{(p,q) \in \mathrm{cell}} I_{p,q}\Big)
```

最近傍拡大は常にこの範囲内にあるので、解が存在します。マスごとの最小値・最大値は、チャンネルプレーンごとに一度だけ作っておきます（`cellRange` キャッシュ）。

### 4.5 原画像整合補正

結果を面積平均で縮小し直す演算を $`D`$ とすると、目標は $`D(U) = I`$ です。初期推定 $`U_0`$ に、原画像解像度の係数 $`c`$ を双線形補間 $`P`$ で展開して加えます。

```math
U = U_0 + P(c),\qquad D(U_0 + P c) = I \;\Longrightarrow\; K c = I - D(U_0),\quad K = D P
```

$`D`$ と $`P`$ はどちらも軸ごとに分離できるので $`K = K_x \otimes K_y`$ であり、各軸の $`K`$ は三重対角行列です。したがって $`c`$ をトーマス法で原画像解像度において厳密に解きます。軸ごとの係数は、出力画素が原画像上に占める範囲（端数の重なりを含む）から作ります。逆行列の減衰は画素ごとに約0.17倍なので、7画素より外の影響は $`0.17^7 \approx 4 \times 10^{-6}`$ 以下です。そのため、タイルごとに7画素の余白を取って解いても、全体を一度に解いた場合と同じになります。

### 4.6 交互投影

整合条件 $`\{U : D U = I\}`$ はアフィン集合で、セル範囲 $`\{U : m \le U \le M\}`$ はボックス集合です。どちらも凸集合なので、交互に投影すると共通部分に近づきます。

```math
U^{(k+1)} = \Pi_{\mathrm{box}}\Big(\Pi_{\mathrm{affine}}\big(U^{(k)}\big)\Big),\qquad k = 0, 1
```

Upscaly は2回（セル範囲が無効なら整合を1回）投影します。整合の投影は厳密な直交投影ではなく $`P`$ 方向への補正であり、最後の投影がセル範囲なので、新しい極値を作らないという約束は常に守られます。

### 4.7 Richardson–Lucy デコンボリューション

ぼけを標準偏差 $`\sigma`$ のガウシアン $`h`$ とみなし、観測 $`o`$ から推定 $`e`$ を乗算型で更新します。

```math
e^{(t+1)} = e^{(t)} \cdot \left( h \ast \mathrm{clip}\!\left(\frac{o}{h \ast e^{(t)}}\right) \right)
```

比率は発散しないようにクリップします。乗算型の更新は定数倍を保存するので、乗算済みの色とアルファに同じ回数を適用すれば、同じ色の領域では色/アルファの比率がそのまま保たれます。

### 4.8 ノイズ除去（バイラテラルフィルタ）

横・縦に分けて適用し、明るさの差の重みは1,025要素の表にして指数関数の呼び出しを避けます。

```math
\hat I_p = \frac{\sum_q w_s(\|p - q\|)\, w_r(|G_p - G_q|)\, I_q}{\sum_q w_s(\|p - q\|)\, w_r(|G_p - G_q|)}
```

$`G`$ はガンマ近似の明るさです。アルファプレーンも同じ重みで平均します。

### 4.9 DCT 精密復元

**ノイズモデル。** チャンネル（Y、Cb、Cr）ごとに、8×8 DCT の周波数ごとの分散 $`S_c[k]`$ と明るさの区間ごとのゲイン $`g_c(I)`$ でノイズを表します。

1. 高周波（$`u + v \ge 6`$）のエネルギーが小さいブロックを繰り返し選び、周波数ごとの平均からスペクトルの形を得ます。質感（テクスチャ）のエネルギーは低周波に集まるので、選択とゲインには高周波だけを使います。
2. 輝度には PCA ノイズフロアで上限を設けます。弱い質感ブロックの63次元共分散のうち、最も小さい固有値3つの平均です。質感はいくつかの方向にしか広がらず、ノイズは63方向すべてに広がるので、質感をノイズと誤認して消すことを防げます。標本数が有限であることは、Marchenko–Pastur の下限 $`\gamma = \sqrt{n / n_{\mathrm{sel}}}`$ で補正します。
3. 不確かなときは少なめに推定する側（細部を守る側）に偏るようにしました。8ビット量子化ノイズ（$`1/12`$）だけが残ったきれいな画像は、事実上0とみなします。

**ノイズ除去。** 移動 8×8 DCT で、BM3D からブロックマッチングを除いた2段階の構造です。ブロック平均の明るさ $`\bar I`$ から、係数ごとのノイズ分散を $`\sigma_k^2 = S[k]\, g(\bar I)\, \lambda^2`$ とします（$`\lambda`$ は強さ）。$`F_k`$ は入力ブロックの係数、$`B_k`$ は第1段階の結果画像の同じブロックの係数です。

```math
\text{第1段階: } \hat F_k = F_k \cdot \mathbf{1}\big[\,F_k^2 \ge \tau^2 \sigma_k^2\,\big],\qquad
\text{第2段階: } \tilde F_k = F_k \cdot W_k,\quad W_k = \frac{B_k^2}{B_k^2 + \sigma_k^2}
```

重なったブロックは、カイザー窓（$`\beta = 2`$）と、BM3D と同様にブロックごとに第1段階では $`1/(1 + n_{\mathrm{nz}})`$、第2段階では $`1/\sum_k W_k^2 \sigma_k^2`$ の重みで合成します（$`n_{\mathrm{nz}}`$ は残った係数の数）。ブロック格子をグローバル座標に固定しているので、タイルの継ぎ目がありません。

**JPEG 量子化区間への投影（QCS）。** JPEG であれば、ファイルの量子化テーブル $`q_k`$ から量子化ノイズの分散をノイズモデルに加え、輝度の DCT 係数を観測された量子化値のまわりの区間へ戻します。エントロピー符号化データは復号しないので、観測係数はデコードされた画像をファイルの 8×8 格子に合わせて DCT した値 $`G_k`$ を、量子化テーブルで丸めて得ます。

```math
c_k = q_k \cdot \mathrm{round}\!\left(\frac{G_k - \ell_k}{q_k}\right) + \ell_k,\qquad
F_k \leftarrow \mathrm{clip}\big(F_k,\ c_k - \Delta_k,\ c_k + \Delta_k\big),\qquad
\Delta_k = \tfrac12 \rho_k q_k + \delta_k
```

$`\ell_k`$ は DC にだけある128レベルのシフトです。0でない値で記録された交流係数のうち最低周波を除いたもの（$`u + v \ge 2`$、エンコーダーが残した実際の質感）は $`\rho_k = \rho`$（既定0.5）で区間を狭めて質感の強さを守り、0係数・DC・最低周波（ブロックとリンギングの原因）は $`\rho_k = 1`$ で区間全体を使ってアーティファクトを消します。$`\delta_k = 2.5\sigma_k`$（交流のみ）は、ノイズが混ざったまま圧縮された場合にそのノイズを消す余地です。（ノイズ除去 → 投影）を2回繰り返し、2回目は量子化ノイズの分散を半分にして使います。

**色。** 色プレーンも同じ方法で処理した後、4:2:0 のような色サンプリングでにじんだ色の境界を、ガイデッドフィルタで復元された輝度の輪郭に合わせます（局所的に 色 $`= a \cdot`$ 輝度 $`+ b`$）。

**細部の復元。** JPEG でない場合、取り除いた量の局所エネルギー $`v`$ がノイズモデルで説明される量 $`\tau \sigma^2`$ を超えるとき、その超過の割合だけ戻します。

```math
\hat I \leftarrow \hat I + \mu \left(1 - \frac{\tau \sigma^2}{v}\right)(I - \hat I)\qquad (v > \tau \sigma^2)
```

### 4.10 アンシャープマスク（ハロー抑制）

ディテール $`d = I - G_\sigma \ast I`$ と局所振幅 $`A = G_{2\sigma} \ast |d|`$ を求めた後、次の順に処理します。

```math
d \leftarrow d \cdot \frac{d^2}{d^2 + t^2}\ \ (\text{平坦部の保護}),\qquad
d \leftarrow a\, d,\qquad
d \leftarrow \frac{d}{1 + |d| / (o A + 10^{-4})}\ \ (\text{ハロー許容量})
```

$`a`$ は強さ、$`t`$ は平坦部の保護、$`o`$ はハロー許容量です。最後の式はニーが滑らかなリミッターなので、大きな輪郭でもオーバーシュートが局所振幅の $`o`$ 倍を超えません。半径0は倍率に合わせて自動で決めます。

### 4.11 方向平滑化（階段除去）

原画像から構造テンソル $`J = G \ast (\nabla Y \nabla Y^{\top})`$ を求め、小さい固有値の固有ベクトルを接線方向 $`\mathbf t`$ とし、大きい固有値 $`\lambda_1`$ から強さ $`w = \min(1, \lambda_1 / 0.0016)`$ を決めます。拡大結果では接線方向にだけ平均します。

```math
\bar U = 0.34\,U(\mathbf x) + 0.22\,\big(U(\mathbf x + \ell \mathbf t) + U(\mathbf x - \ell \mathbf t)\big) + 0.11\,\big(U(\mathbf x + 2\ell \mathbf t) + U(\mathbf x - 2\ell \mathbf t)\big),\qquad
U \leftarrow U + w\,\kappa\,(\bar U - U)
```

階段の周期は倍率と同じなので、歩幅 $`\ell`$ は倍率の0.8倍（1〜8）に合わせます。1回では足りないので、強さに比例して1〜4回繰り返します。繰り返すほど揺らぎは乗算的に減り、遷移幅はそのままです。方向場はグローバル座標で求めるので、タイル境界でも同じ値になります。

### 4.12 輪郭再描画（符号付き距離）

原画像の 5×5 窓の暗い色と明るい色 $`(\mathrm{lo}, \mathrm{hi})`$ を結ぶ線分上に画素が並び、変化が1〜2画素以内で起きていれば輪郭とみなします。拡大結果を線分上の位置 $`t \in [0, 1]`$ に変換し、0.5 等値線までの符号付き距離で1画素幅のランプを描き直します。

```math
t' = \mathrm{clip}\!\left(0.5 + \frac{t - 0.5}{|\nabla t|},\ 0,\ 1\right),\qquad
U \leftarrow U + \gamma\,w_{\mathrm{fit}}\big(\mathrm{lo} + t'(\mathrm{hi} - \mathrm{lo}) - U\big)
```

$`|\nabla t|`$ は出力画素あたりの勾配です。実際の計算では $`U + (t' - t)(\mathrm{hi} - \mathrm{lo})`$ を $`[\mathrm{lo}, \mathrm{hi}]`$ にクリップした値を目標に使い、混合の重み $`\gamma\,w_{\mathrm{fit}}`$ は、原画像解像度で再描画の強さと適合度（中央の 3×3 が線分からどれだけ外れているか）から作った重みを双線形に展開した値です。50%等値線による再描画は幅が1画素を超える線でしか面積（濃度）を保存しないので、線を横切る積分濃度で測った幅が1画素前後の細い線には手を加えず、うねりを防ぎます。

### 4.13 ピクセルアートの輪郭復元

形は DCCI の場が決め（45°・2:1 の階段がまっすぐな線になる）、色は各サブサンプルが属する原画像の 2×2 マスの元の4色のうち、場の値に最も近い色に固定します。出力画素ごとに 4×4 のサブサンプルを平均して輪郭だけをアンチエイリアスするので、新しい色は輪郭の境界にしか生じません。マスの4色が同じなら高速経路で飛ばします。

### 4.14 ホワイトバランスの合意

「色自動」は分析画像（線形光）から飽和（0.95以上）とほぼ黒（0.004以下）の画素を除き、3つの推定器で光源の色を求めます。

```math
e^{\mathrm{sog}}_c = \Big(\tfrac1n \sum f_c^{6}\Big)^{1/6},\qquad
e^{\mathrm{ge}}_c = \Big(\tfrac1n \sum |\nabla (G \ast f_c)|^{6}\Big)^{1/6},\qquad
e^{\mathrm{wp}}_c = Q_{0.99}(f_c)
```

シェード・オブ・グレイ（平均）、グレイエッジ（エッジ）、ホワイトパッチ（明るい面、99パーセンタイル）です。$`G`$ は $`[1,4,6,4,1]/16`$ の平滑化です。各推定が中立 $`(1,1,1)`$ となす角度 $`\theta`$ から強さ $`a`$ を決めます。

```math
a =
\begin{cases}
0 & \theta_{\min} < 3^\circ \ \text{または}\ \theta_{\min} > 28^\circ \ \text{または}\ \theta_{\max} - \theta_{\min} > 10^\circ \\[2pt]
\min\!\big(1,\ \theta_{\min} / \theta_{\mathrm{sog}}\big) \cdot h,\quad h = \begin{cases} \tfrac12 & \theta_{\mathrm{wp}} < 0.8\,\theta_{\mathrm{sog}} \\ 1 & \text{それ以外} \end{cases} & \text{それ以外}
\end{cases}
```

3つの条件は順に、偏りがない、照明とはみなしにくい場面固有の色、混ざった照明です。明るい面が平均より色づいていなければ、被写体の色が平均を引っ張ったものとみなして半分だけ補正します。強さは0.05単位で丸めます。処理するときは、半透明（アルファ0.5未満）・飽和・ほぼ黒の画素を除いた最大15万画素からチャンネルゲインを求め、全体の輝度（$`0.2126R + 0.7152G + 0.0722B`$）を保つように正規化し、$`1 + (g - 1)a`$ で混ぜた後、0.55〜1.8にクリップします。

### 4.15 9種分類器

27次元の特徴 $`\mathbf x`$ を学習時の平均・標準偏差で標準化した $`\mathbf z`$ に、多項ロジスティック回帰を使います。

```math
P(k \mid \mathbf x) = \frac{\exp(\mathbf w_k^{\top} \mathbf z + b_k)}{\sum_j \exp(\mathbf w_j^{\top} \mathbf z + b_j)}
```

種類ごとに標本数が異なるので種類のバランス重みを置き、L2 正則化した交差エントロピーを L-BFGS-B で最小化しました。JPEG 品質の影響を受ける特徴（単色ブロック、ノイズのないブロック、ノイズフロア、滑らかなブロック）には、品質の信頼度 $`r = \mathrm{clip}((q - 50)/40,\ 0.05,\ 1)`$ を掛けます。判定の根拠は、1位 $`k_1`$ と2位 $`k_2`$ のロジット差に対する特徴ごとの寄与 $`z_j (w_{k_1 j} - w_{k_2 j})`$ の大きい順です。

### 4.16 レンダリング予算

倍率 $`L`$、原画像の画素数 $`n_0`$、結果の画素数 $`N`$ から、段階ごとの最大メモリを次のように見積もります（バイト）。

```math
\begin{aligned}
M_{\mathrm{prep}} &= \max\big(32\,n_0,\ \ 4 c\, n_0 + 32\, n_0 s_k^2\big) && \text{原画像の準備、段階拡大の中間段階} \\
M_{\mathrm{fixed}} &= M_{\mathrm{other}} + M_{\mathrm{src}}^{1} + M_{\mathrm{keep}} + n_w (T + 64 + 2t + 2p)^2 (48 + 24[t > 0] + 32[p > 0]) + 1.5\,W \max(4T, 1024) + 1.1\,\rho\, c\, b\, N && \text{他の原画像・準備済み原画像、残るプレーン、ワーカーのタイル、保存の帯、圧縮 PNG} \\
\text{保証} &\iff M_{\mathrm{other}} + M_{\mathrm{src}}^{2} + M_{\mathrm{prep}} \le 0.8B \ \wedge\ 0.8B - M_{\mathrm{fixed}} \ge 4 \min\big(N, \max(4 \times 10^6, 2WT)\big)
\end{aligned}
```

$`c`$ はチャンネル数、$`s_k`$ は段階拡大の中間倍率、$`n_w`$ はワーカー数、$`T`$ はタイルサイズ、$`t`$ は質感復元の結果側の余白（無効なら0）、$`W`$ は結果の幅、$`B`$ はメモリ予算です。$`M_{\mathrm{src}}^{2}`$ はキャッシュに残っている他の準備済み原画像すべて（新たに準備している間は両方が残る）、$`M_{\mathrm{src}}^{1}`$ はそのうち最新の1つ（新しいものを入れると1つだけ残る）です。$`b`$ はチャンネルあたりのバイト数（8ビットは1、16ビットは2）、$`\rho`$ は保存 PNG の圧縮率の最大値です。`data/big` の47枚を 1.1・1.25・1.5・2・3・4× に拡大し、アプリのエンコーダーで測定しました。2× 以上はプリセットだけを使った場合と、「自動」の拡大復元の探索値（`AUTO_BIG`）まで使った場合の両方を測って大きい方を、2× 未満は探索値を使わないのでプリセットだけを採っています（`research/budget/png_ratio.js`、`research/results/png_ratio.json`）。結果の倍率を挟む2つの測定倍率のうち大きい方の値を使います（4× 以上は 4× の値）。面積倍率 1.25× も縦横では 1.12× なので測定範囲内であり、1.1× 未満は圧縮前のサイズで数えます。 $`p`$ は「体感」の結果の余白（二つのぼかしと近傍の最小・最大、「精度」なら 0）です。圧縮率は「体感」（強さ最大 150%、質感オフ・オン）でも測り、二つの目標のうち大きい値を使います（`research/results/png_ratio_pop.json`）。

| 倍率 | 8ビット 質感オフ | 8ビット 質感オン | 16ビット 質感オフ | 16ビット 質感オン |
|---|---|---|---|---|
| 1.1× | 0.721 | 0.767 | 0.928 | 0.933 |
| 1.25× | 0.686 | 0.766 | 0.913 | 0.928 |
| 1.5× | 0.650 | 0.760 | 0.898 | 0.926 |
| 2× | 0.688 | 0.790 | 0.876 | 0.933 |
| 3× | 0.615 | 0.751 | 0.842 | 0.931 |

8ビットはディザを有効にした値で、質感オンは25%と100%のうち大きい方です。最後の項は、保存に必要なタイル2行分（最小4メガ画素）のキャッシュです。メモリ予算 $`B`$ は `navigator.deviceMemory` の15%（400〜1500 MB）、それがなければ JS ヒープ上限の50%（最大1500 MB）、それもなければ600 MB です。モバイルは12%（最大400 MB、なければ180 MB）です。

### 4.17 8ビットディザ

丸める直前の連続 sRGB 値 $`s = 255\,\mathrm{srgb}(v)`$ に、結果の座標 $`(X, Y)`$ だけで決まるインターリーブド・グラディエント・ノイズ（IGN、Jimenez 2014）を加えます。

```math
\nu(X, Y) = \mathrm{frac}\!\big(52.9829189 \cdot \mathrm{frac}(0.06711056\,X + 0.00583715\,Y)\big) - \tfrac12,\qquad
b = \big\lfloor s + \tfrac12 + 0.98\,\nu \big\rfloor
```

振幅が±0.49段階なので、$`|s - k| < 0.01`$ である値（正確なコード値 $`k`$）はそのまま $`k`$ になります。連続 sRGB 値は16ビットエンコーダーの $`\sqrt v`$ 軸の表を補間して得ており、補間誤差は最大0.002段階です。3チャンネルに同じ $`\nu`$ を使い、アルファにはディザをかけません。

### 4.18 質感復元

原画像（線形光、乗算済み）のガンマ近似の明るさ $`Y = \sqrt{\ell}`$、$`\ell = 0.2126R + 0.7152G + 0.0722B`$ から、2番目に細かい帯域の局所的な強さと輪郭マスクを測ります。

```math
a = \mathrm{erode}_{5\times5}\!\left(\sqrt{G_{1.5} \ast (G_1 \ast Y - G_2 \ast Y)^2}\right),\qquad
m = \big(1 - c^2\big)^2,\quad c = \frac{\sqrt{(J_{xx} - J_{yy})^2 + 4J_{xy}^2}}{J_{xx} + J_{yy}}
```

$`G_\sigma`$ はガウシアン、$`J = G_{1.5} \ast (\nabla Y \nabla Y^{\top})`$ は構造テンソル、$`c`$ は方向の一致度です。5×5 の最小値（収縮）は、輪郭・細い線・角のように幅の狭い強い構造の強さを消し、広く分布した質感だけを残します。$`m`$ は一方向に伸びた輪郭で0に近づきます。

結果の解像度（倍率 $`L`$）で、原画像のナイキスト周波数より上の帯域だけを残した単位分散のノイズを作ります。$`h(X,Y,s)`$ は整数ハッシュを [0, 1) に変換した値です。

```math
n = \sqrt3\Big(\textstyle\sum_{s=1}^{4} h(X, Y, s) - 2\Big),\qquad
\eta = \frac{n - G_{0.375L} \ast n}{\sqrt{1 - 2k_0^2 + (\sum_i k_i^2)^2}}
```

$`k_i`$ は1次元ガウシアンカーネルで、分母はこの差分の分散を正確に1に合わせます。$`\sigma = 0.375L`$ は、原画像のナイキスト周波数で応答が半分になる値です。目標の分散と、結果にすでにある同じ帯域の分散から、欠けている分だけを載せます。

```math
T = \big(\alpha\, C\, \sqrt{\log_2 L}\; a\, m\big)^2,\qquad
E = G_{0.5L} \ast \big(Y_U - G_{0.375L} \ast Y_U\big)^2,\qquad
\Delta = \mathrm{clip}\!\big(\sqrt{\max(0, T - E)}\;\eta,\ \pm 0.4\,Y_U\big)
```

$`\alpha`$ は強さのスライダー、$`C = 6.256`$ は測定で合わせた定数（[9.8](#98-質感復元)）、$`Y_U`$ は結果のガンマ近似の明るさです。最後に3チャンネル（乗算済み）に同じ比率 $`f = \big((Y_U + \Delta)/Y_U\big)^2`$ を掛け、色相とアルファをそのまま保ちます。明るくするとき（$`f > 1`$）は、最大のチャンネルが上限（アルファ、不透明なら1）を超えないように $`f \le \max\!\big(1,\ \min(1, A) / \max(R, G, B)\big)`$ に抑えます。そうしないと、明るく彩度の高い色で1つのチャンネルだけがクリップされて色相が変わります（例: 250・127・73 が 255・130・76 に。v1.1.1 で修正）。ノイズ・原画像の統計・結果のエネルギー窓がすべてグローバル座標で決まり、その分の余白を余計に計算するので、タイルに関係なく結果は同じです。

### 4.19 色域判別と Display P3 プロファイル

ICC プロファイルの原色行列 $`(\mathbf r, \mathbf g, \mathbf b)`$（D50 基準の XYZ）を sRGB の値と比較し、1つの成分でも0.02を超えて異なれば広色域とみなします。行列のない LUT プロファイルは説明文字列（P3、Adobe、2020、ProPhoto）で判断します。PNG の cICP と AVIF の nclx は、原色番号が1（BT.709 = sRGB）や2（未指定）でなければ広色域とみなします。AVIF・HEIF は `meta` ボックスの `pitm`（主項目）と、`iprp` の中の `ipma`（項目 ↔ プロパティ番号）・`ipco`（プロパティ）を読み、主画像に関連付けられた `colr` だけを見ます。サムネイルや補助画像の `colr` が前にあっても、主画像が基準です。この構造を読めなければ、最初に出てくる `colr` を使います。

保存時に付ける Display P3 プロファイルは、アプリが自分で作ります（ICC v4.3、532バイト）。原色は、P3 の色度座標 (0.680, 0.320)、(0.265, 0.690)、(0.150, 0.060) と D65 白色から RGB→XYZ 行列を求め、ブラッドフォード変換で D50 に合わせた値です。

```math
\mathbf r = (0.515119,\ 0.241189,\ -0.001050),\quad
\mathbf g = (0.291978,\ 0.692244,\ 0.041879),\quad
\mathbf b = (0.157103,\ 0.066567,\ 0.784071)
```

曲線は sRGB と同じパラメトリック曲線（形式3: $`\gamma = 2.4`$、$`a = 1/1.055`$、$`b = 0.055/1.055`$、$`c = 1/12.92`$、$`d = 0.04045`$）です。この値は Apple の Display P3 プロファイルの原色と $`10^{-5}`$ 以内で一致します。

### 4.20 測定指標

```math
\mathrm{PSNR} = 10 \log_{10} \frac{255^2}{\frac{1}{3n}\sum (U - I_{\mathrm{gt}})^2},\qquad
E_{\mathrm{dir}} = \frac{\sum_p m_p\, \arccos\!\big(|\hat{\mathbf g}^{U}_p \cdot \hat{\mathbf g}^{\mathrm{gt}}_p|\big)}{\sum_p m_p}\quad (m_p \ge 80)
```

$`E_{\mathrm{dir}}`$ は境界方向誤差です。原画像の強い境界（Sobel の大きさ80以上、約20段階の段差）で、結果と原画像の勾配方向がずれた角度を境界の強さで重み付け平均します。階段が生じると勾配方向が軸の側に偏るので大きくなります。SSIM は Wang ら（2004）の定義を使います。

### 4.21 体感シャープネス

「体感」モードでは、結果の輝度 $`Y`$（線形光なら $`\sqrt{\ell}`$、ガンマ値なら $`\ell`$。$`\ell`$ は 0〜上限で切ったチャンネルの輝度）に二つの帯域を加えます。$`L`$ は倍率、$`G_\sigma`$ はガウシアン（箱型 3 回の近似）、$`a`$ は体感の強さです。

```math
d_1 = Y - G_{0.5L}Y,\qquad d_2 = G_{0.5L}Y - G_{2L}Y,\qquad
\tilde d = d\,\frac{d^2}{d^2+\tau^2}\quad(\tau = 0.004)
```

```math
\Delta = a\Big(k_1\,\tilde d_1 + k_2\,\frac{\tilde d_2}{1+|\tilde d_2|/c_2}\Big),\qquad
Y' = Y + \Delta\,\frac{h}{h+|\Delta|},\qquad
h = \begin{cases}\max_{\mathcal N}Y - Y & \Delta>0\\ Y-\min_{\mathcal N}Y & \Delta\le 0\end{cases}
```

$`d_1`$ は原画像のナイキスト付近の輪郭の傾き、$`d_2`$ は原画像 1〜4 画素の大きさの局所コントラストです。$`\tilde d`$ はアンシャープと同じ形のしきい値で、ノイズや JPEG の痕跡のような小さな振幅はほとんど上げません。局所コントラストは振幅が大きいほど上げ幅を小さくし（$`c_2 = 0.05`$）、すでにはっきりした明暗はそのまま、埋もれた明暗を浮き立たせます。$`\mathcal N`$ は半径 $`\mathrm{round}(0.75L)`$ の正方形の近傍（画像内のみ）、$`h`$ は近傍の最小・最大までの余裕です。$`\Delta\,h/(h+|\Delta|)`$ は余裕に滑らかに近づくだけで越えないので、新しい極値（ハロー）は生じず、境界に張り付かないので面が固まりません（ポスタリゼーションしません）。最初は近傍の範囲でぴったり切る方式でしたが、面が固まって油絵のように見えたため変えました。変えた輝度は比率 $`s = Y'/Y`$（線形光なら $`s^2`$）として、乗算済みの色 3 チャンネルに同じだけ掛けるので、色相・グレー・アルファはそのままです。明るくするときは、最大のチャンネルが上限を超えないよう比率を縮めます（質感復元と同じ処理）。 アルファがあるときは乗算を解除した色で輝度を測り、ぼかしは不透明度で重み付けした平均とし、近傍の最小・最大からはほぼ透明な画素（アルファ 2% 未満）を除きます。そのため、色は同じで不透明度だけが変わる境界には縁取りが生じません。

$`k_1 = 0.5`$、$`k_2 = 1.5`$ は探索用画像で選んだ値です。$`k_1 \in \{0.5, 1, 2, 3\}`$ × $`k_2 \in \{0, 0.5, 1, 1.5\}`$ の 16 通りを 22 枚 × 3 条件（4× クリーン・4× 劣化・8× 劣化、66 件）で測り、正解に対する輪郭の傾き $`A`$ と局所コントラスト $`C`$ の対数誤差 $`|\ln A| + |\ln C|`$ の中央値を比べました。$`A`$ は両方を $`\sigma = 0.5L`$ でぼかしたあと、正解の輪郭（傾きの上位 10%）で測った傾きの比、$`C`$ は $`G_{0.5L}-G_{2L}`$ 帯域の RMS の比です。16 通りすべてが「精度」（0.418）より誤差が小さく（0.343〜0.410）、そのうちハローと平坦面のノイズの増え方が小さいものを選びました（誤差 0.357、ハロー +0.20 段階、平坦面ノイズ ×1.14、SSIM +0.004）。結果は `research/results/pop_grid.json` にあります。

### データの流れとキャッシュ

画像ごとに、原画像のキャンバス、JPEG の格子・品質、ノイズモデル（最初に必要になったときに一度だけ）、被写体ボックス、設定を別々に保持しています。結果は作成時の設定のスナップショットを持っているので、後で設定を変えても、保存と再計算はその結果と同じ値を出します。

結果タイルは LRU キャッシュに置きます。キャッシュの上限はメモリ予算の60%で、実際にキャンバスの作成に失敗したときは、その時点のキャッシュサイズの80%をこの端末の上限として学習しておきます。倍率自動が選んだ倍率では、保証条件に従って上限をさらに下げます。キャッシュに収まりきらない結果は、中央からキャッシュの半分だけを先に計算し、残りは画面に表示されるときか保存するときに計算します。画面に見えているのにまだないタイルは、原画像の拡大で場所を埋め、裏で計算を任せます。

### 決定性: 画面 = 保存結果

画面、保存、再計算はすべて同じ `renderTile` を使います。近傍を参照する処理（補間、整合、アンシャープ、方向平滑化、再描画）は、必要な半径の分だけ余白を余計に計算してから切り取り、DCT のブロック格子と方向場はグローバル座標に固定しています。そのため、タイルのサイズ・順序・ワーカー数に関係なく結果は同じです。64px のタイルに細かく分けて計算してもタイルの継ぎ目は最大1段階以内で、同じ設定を2回計算した差は0です（[9.1](#91-不変条件)）。

## 7. 課題と解決

### 画質

| 課題 | 原因 | 解決 |
|---|---|---|
| 輪郭まわりの白い縁取り（リンギング・ハロー） | カーネルの負のすそが原画像にない極値を作る | DCCI の4近傍クリップ、セル範囲制限、アンシャープのニーリミッター |
| 結果を縮小すると原画像と異なる | 補間が原画像の標本を通っても、面積平均は一致しない | 整合補正を原画像解像度で厳密に解く（トーマス法） |
| 整合とセル範囲が互いを崩す | 一方を満たすともう一方がずれる | 交互投影を2回 |
| 半透明の縁の色にじみ（合成誤差最大29段階） | アルファと色が異なる演算を通っていた | アルファも色と同じ演算を通すようにした（0.1〜4段階） |
| 段階拡大がかえって悪化（−0.4〜−0.8 dB） | セル範囲・整合の基準を中間画像に置いていた | 基準を原画像に（+0.03〜0.06 dB） |
| 線画で原画像の階段がよみがえる | 整合は原画像の階段を正解とみなす | 線画・ロゴは再描画と方向平滑化、探索で種類ごとに整合の有無を決める |
| 細い線がうねる | 50%等値線による再描画は1画素より細い線の濃度を保存できない | 積分濃度で線幅を測り、細い線はそのままにする |
| ノイズの中で DCCI が方向を誤判定 | ノイズが方向の変化量を揺らす | 変化量にノイズフロア $`n_{\mathrm{off}}`$ を加える（Immerkær σ） |
| 質感をノイズと誤認して消す | 質感ブロックがノイズスペクトルを膨らませる | PCA ノイズフロアで上限、高周波だけで選択 |
| JPEG 復元がファイルの細部まで消す | ノイズ除去だけでは元の係数がわからない | 量子化区間への投影（QCS） |

| 課題 | 原因 | 解決 |

## 8. 最適化

速度の最適化は、出力がバイト単位で同じ場合にだけ取り入れました。134通りの設定の組み合わせについて、16ビット出力と統計を基準版と照合します（`tests/engine_regression.js`）。ただし、下の表の1行目である DCCI 内部格子の表は例外です。出力がわずかに変わる（±0.007 dB）代わりに速くなることを測定して採用した妥協であり、現在の基準版はこの表が入った後の版です。

| 最適化 | 内容 | 効果 |
|---|---|---|
| DCCI 内部格子の表 | 6・8・12× で8倍格子の代わりに4倍格子。25個のプリセット × 1,800組で±0.007 dB 以内 | 25〜30%高速 |
| DCCI の方向重みの共有 | ガイドプレーンで一度計算し、全チャンネルに使う | |
| セル範囲のキャッシュ | チャンネルプレーンごとに、マスごとの最小値・最大値を一度だけ | |
| 整合のチャンネル一括処理 | チャンネルプレーンをまとめて詰め直すコピーなしに、範囲・係数・補間の重みを共有 | |

### 9.7 8ビットディザリング

同じ処理の16ビット出力を基準に、8ビット出力の誤差を測ります（`tests/dither_probe.js`）。帯指標は、誤差をガウシアン σ2（結果の画素単位）でぼかした後の RMS です。帯は広い面にわたる低周波の誤差なのでぼかしても残り、ディザの細かな質感はぼかすと消えます。合成した空のグラデーションと、拡大復元の検証用の写真・絵画・イラストの断片9枚を4・8倍に拡大した20件です。

| 帯指標 σ2 | 0.059 | 0.033 | −44%（8× で約 −50%） |
| 帯指標 σ4 | 0.040 | 0.017 | −58% |
| 全体 RMS | 0.245 | 0.340 | +39% |

全体 RMS は、ディザが細かなノイズを加える分だけ増えます。ディザを有効にしても、最近傍 3× 出力のずれた値は0個、白黒入力の R・G・B 最大差は0です。

### 9.8 質感復元

拡大復元のデータ（256px の正解 → 4・8倍に縮小 → 再び拡大）で、原画像のナイキスト周波数より上の帯域（ガウシアン σ = 0.375・倍率の差分）のエネルギーで測定します（`research/texture/tex_probe.js`、結果は `research/results/texture*.json`）。

- **高周波エネルギー比 R** = 結果 / 正解。拡大はこの帯域を作れないので、R は1よりずっと小さくなります。
- **質感マップ誤差** = 16×16 ブロックの高周波エネルギーの log 比の RMS。質感があるべき場所にあるかを見ます。
- **PSNR・SSIM。** 作り出した質感は正解と位置が合わないので、下がるのが正常です。

**定数の調整。** 写真の探索用3枚 × （4× きれいな入力、4×・8× 現実的な劣化）の9件で、割線法により R = 1 となる定数を求め、R を合わせられた8件の中央値 $`C = 6.256`$ を100%と定めました（v1.1.0 は5.915。明るくするときにチャンネルの余裕で抑えるようになったため、少し大きくなりました）。設定は「自動」と同じく、縮小された入力を分類して選んだプリセット・探索値です。画像ごとに2.4〜12と広く散らばります。質感の量が写真ごとに異なり、原画像の1つの帯域だけでは欠けたエネルギーを正確に見積もれないためです。正解画像で検討すると、原画像の2番目の帯域 × オクターブ数が、試した4つの予測式のうち写真で最も正確でした（エネルギー ×÷1.45）。

**検証（写真の検証用3枚 × 4条件 = 12件）。**

輪郭の傾きと局所コントラストが正解に近づき、ハローと平坦面のノイズはほとんど増えません。写真・絵は 2/3 以上で改善しますが、線画・文書・UI・ロゴは 20/35 で半分を少し超える程度です。もともと輪郭が急な画像なので、局所コントラストが正解より大きくなりやすいためです。比較画像は `research/results/pop_samples/` にあります（左から正解・精度・体感 50%・100%・150%。4× 劣化と、500px の正解を半分に縮めて 2× 拡大した場合）。

最初は「体感」に細かな質感（質感復元、強さ 100% で 25%）も一緒に載せていました。質感の指標（高周波エネルギー比 R 0.13 → 0.30）は改善しましたが、平坦面のノイズが 4.0 倍になり SSIM が −0.044 下がって（`pop_val_grain.json`）、なめらかな面に点が見えました。そのため「体感」は輪郭と局所コントラストだけを上げ、細かな質感は別に「質感復元」スライダーで選ぶようにしました。

## 10. 特長

**情報に正直な復元。** 復元段階では新しい極値を作らず（セル範囲）、縮小し直せば原画像になるように（整合）合わせます。その上の補正は、ユーザーが有効にした分だけ載せます。

**種類を理解する自動。** 9種分類（92.9%）と1.52兆通りの設定探索、画像ごとの測定によって決めます。何を根拠に決めたかを画面に表示します。

**原画像の解像度で完結する復元。** ノイズスペクトルを測って取り除く DCT 復元、ファイルの量子化テーブルを守る JPEG 復元、RL デコンボリューションを拡大の前に行います。

**線が生きたグラフィック。** 方向平滑化と符号付き距離による再描画で、階段のないシャープな線を作ります。ピクセルアートはサブサンプルごとに元のパレットの色だけを選び、新しい色は輪郭のアンチエイリアシングにしか生じません。

**正直なユーザー設定。** チェックとスライダーは選んだとおりに動作します（画像を開いた直後の例外は [11. 限界](#11-限界)）。自動化は「自動」ボタンだけが行い、表示灯は測定結果を知らせるだけです。

**サイズに縛られない。** タイルキャッシュとタイル行単位の PNG 圧縮により、圧縮していない結果全体をメモリに載せずに、数億画素の結果も保存します。倍率自動は、メモリ予算を基準に最後まで処理できる倍率だけを選びます。

**画面 = 保存。** 同じカーネル、余白、グローバルな格子によって、画面で見たものがそのまま保存されます。

**帯のない8ビット。** 座標で決まるディザで帯指標を半分近くまで減らしながら、正確な色・灰色・タイルの継ぎ目はそのまま保ちます。

**スマートフォンの色をそのまま。** 原画像のプロファイルを読んで Display P3 写真を P3 で処理し、自前で作った P3 プロファイルと cICP を付けて保存します。

**プライバシーと可搬性。** サーバーもインストールもなく、画像が端末の外に出ません。ファイル1つなので、保管も持ち運びも簡単です。

## 11. 限界

**作り出さない。** 原画像に記録されていない細部（髪の毛1本、小さな文字）は取り戻せません。ニューラルネットワークによる拡大のようにもっともらしい形を描き込むことはしないので、ひどくぼけた原画像は大きく拡大してもぼけたままです。

**質感復元はグレインである。** 質感の量は合わせますが、位置と形は作り出したノイズなので、強さを上げるとノイズのように見えます。100%では絵画は大きく過剰になります。イラストは効果が小さく、平坦なグラフィックはどの強さでも半分程度しか改善しません。写真・絵画に弱い強度でのみ推奨します（[9.8](#98-質感復元)）。

**「体感」は情報を増やさない。** 原画像が持つ輪郭と明暗を目立つように描き直すだけで、原画像になかった細部は作りません。線画・文書・UI・ロゴのように輪郭がもともと急な画像では、改善するのは半分を少し超える程度です（20/35）。非常に小さな原画像を大きく拡大した結果のようにぼやけた結果は、「体感」を使ってもぼやけたままです（[9.10](#910-体感シャープネス)）。

**ロゴ・漫画は JPEG 入力のみ。** 測り直したきれいな入力で採用規則を通過しなかったので、PNG のようなきれいな入力には拡大復元の探索値を使いません。元は JPEG で PNG に保存し直した画像は、JPEG の痕跡があってもきれいな入力とみなします。

**イラストは不採用。** 条件ごとに結果が分かれるので、拡大復元の探索値を使いません。別の劣化（強いノイズ、別のぼけ、元々鮮明な原画像）や、より大きな画像で検証し直す余地があります。

**探索範囲。** 探索は小さな断片（入力 64px）と種類ごとに3枚を基準にしています。鮮鋭化の量・オーバーシュートなどが範囲の端に張り付く傾向があり、範囲を広げても +0.1 dB 以内でした。

**メモリだけを見る倍率自動。** 処理時間の制限はありません。8× だと結果は数百メガ画素になります。メモリ予算は端末メモリの推定値なので、「保証」（보장）はこの予算を基準にしたものです。ブラウザが残りのメモリを正確に教えてくれないためです。

**8ビット入力の階調。** 入力はブラウザのキャンバスを通して8ビットで読み込まれます。ディザリングと16ビット保存は拡大によって新たに生まれた中間値を守るだけで、原画像にすでにあった帯（特に 1× や非常に平坦な面）を消すことはできません。ディザを無効にすると、8ビット保存は単純な丸めになり、帯が倍率の分だけ広がります。

**カラーマネジメント。** 広色域は Display P3 までしか守りません。Adobe RGB・BT.2020・ProPhoto のように P3 を外れる色を持つ原画像は P3 の内側に縮められ、保存 PNG には P3 プロファイルが付きます。キャンバスが作業色空間として sRGB と Display P3 しか提供しないためです。それでも sRGB で読み込むよりは縮みが少なくなります（CIE xy の面積で、BT.2020 の三角形に対して sRGB は53%、P3 は72%）。元のプロファイルのまま守るには、色変換なしで読み込んでその符号化のまま処理し、プロファイルを付け直す必要があるため、別途扱う機能として残しています。P3 キャンバスに対応していないブラウザ（例: 現在の Firefox）は、従来どおり sRGB で読み込みます。貼り付けた画像は常に sRGB とみなします。AVIF が `colr` ボックスを持たず、AV1 ビットストリーム（シーケンスヘッダー）の中にだけ色情報を置いている場合は、読み取らずに sRGB とみなします（libavif のような一般的なエンコーダーは `colr` を書きます）。`DecompressionStream` のないブラウザ（Safari 15.2〜16.3）は PNG の圧縮された iCCP プロファイルを展開できないので、cICP なしで iCCP だけで広色域を示す PNG を sRGB とみなします。「自動」の分析（分類・細部の測定・色自動）は P3 画像もブラウザから sRGB の値として受け取って測るので、分類器が学習した sRGB 基準のままです。ストリーミング圧縮のないブラウザのキャンバス保存経路では、P3 プロファイルを直接付けません。

**圧縮率の仮定。** 倍率自動は、保存 PNG の圧縮率を、データ47枚で倍率ごとに測った最大値に余裕10%を加えて数えます（16ビットで質感を有効にすると 0.934 × 1.1、圧縮前サイズの102%）。47枚よりはるかにノイズの多い画像はこの仮定より圧縮されにくく、「保証」された倍率でも保存中にメモリが不足する可能性があります。

**含まれていないデータ。** 分類器の学習用 RGBA キャッシュ（約 1.3 GB）と DCCI 格子の実験データ（約 1.3 GB）は、サイズの都合でリポジトリにありません。どちらも `data/ds` の原画像から作り直せます。

### v1.2.0 — 正確さと体感、二つの目標

- **「目標：精度・体感」。** 既定の「精度」はこれまでどおり原画像にもっとも近く拡大します（出力は v1.1.1 とバイト単位で同じ）。「体感」は輪郭の傾きと局所コントラストを正解の水準まで上げ、目により鮮明に見せます。周囲の明るさの範囲を超えないので白い縁取りは生じません。検証 70 件で正解に対する誤差が 0.600 から 0.505 に減り、平坦面のノイズは ×1.05、PSNR は −0.12 dB です（[2.9](#29-正確さと体感は別の目標)、[9.10](#910-体感シャープネス)）。
- 体感の強さは 25〜150% で、プリセットと「自動」はこの選択を変えません。倍率自動は「体感」の余白・メモリ・保存 PNG の圧縮率を数えます。

### v1.1.1 — コードレビューで見つかった問題の修正

- **段階拡大した透明画像。** 中間段階でアルファも色と同じ方向の重み・セル範囲・段階間の鮮鋭化を通ります。DCCI 4× で半透明の縁の色誤差が最大19〜38段階から1〜4段階に減り、ロゴプリセット 4× のタイルの継ぎ目（最大206段階）がなくなりました。
- **「段階に分けて拡大」の初期値。** 画像を開いた直後の測定が終わる前にチェックを変えたり「自動」を押したりすると、遅れて終わった測定はその選択を上書きしません。
- **空白キャンバスの確認。** 原画像のキャンバスが丸ごと透明なら原画像を断片ごとに直接読んで見える画素があるかを確かめ、キャンバス保存では結果中の見える画素を1つ探してその位置を確認します。右下が元々透明な画像や、点が1つだけ見える画像でもキャンバスの上限に気づきます。
- **質感復元の明るい色。** 明るくする比率を最大チャンネルの余裕で制限し、明るく彩度の高い色の色相が変わらないようにしました。その分の定数を合わせ直し（5.915 → 6.256）、測定を「自動」と同じ条件に正して測り直しました。「線形光で計算」を外したガンマモードで質感が1.8倍に過剰になっていた問題も直しました。
- **色域の判別。** 色情報の前に 2 MB を超えるメタデータやボックス（JPEG 拡張 XMP、PNG テキストチャンク、meta より前の AVIF mdat）があっても、ヘッダーをたどって見つけます。AVIF はサムネイル・補助画像ではなく主画像に関連付けられた色情報（colr）を見て、PNG はチャンクの順序に関係なく cICP を最優先で見ますが、原色が未指定（2）なら iCCP プロファイルで判別します。広色域ファイルは Blob URL がブロックされても Data URL の `<img>` で読み込み、色を守ります。
- **「自動」の後の予算。** 「自動」は大きい倍率から順にその倍率の「自動」設定を適用してみて、最初に保証された倍率を選びます。最近傍・質感オンで 1200×900 に 8× を選び、原画像の準備でメモリが不足していた問題がなくなりました。倍率によって設定が安い側・高い側に分かれるときに、より小さい倍率にとどまっていた問題もなくなりました（UI 画像 4000×3000、現在の倍率 1.25× で3段階の段階拡大: 「保証なし」→ 2×）。
- **倍率自動のメモリ計算。** 保存中にたまる圧縮 PNG（データ47枚を 1.1〜4× に拡大して測った倍率ごとの最大圧縮率に余裕10%）と、キャッシュに残る他の準備済み原画像を数えます。そのため、大きな写真では選ばれる倍率が下がることがあります（予算 600 MB で 4000×3000 は 4× ではなく 2×）。保存のビット数や質感を変えると、案内も再計算します。

### v1.1.0 — 帯のない8ビット、スマートフォンの色、質感復元、ロゴの再検証

- **8ビットディザリング（既定でオン）。** 8ビットに変換するときに座標で決まる細かなディザを混ぜ、大きく拡大したグラデーションの帯を減らしました（帯指標 −44%）。「8ビットディザリング」（8비트 디더링）のチェックで無効にできます。16ビット出力は v1.0.0 とバイト単位で同じです。
- **Display P3 の保持。** 元ファイルの色プロファイルが sRGB より広ければ P3 キャンバスで読み込み、画面も P3 で描き、保存 PNG に Display P3 プロファイル（cICP・iCCP）を付けます。P3 の赤・緑が以前のように押し込まれません。
- **質感復元（既定でオフ）。** 原画像の質感の強さに合わせて、欠けた細かな質感を載せるスライダーを新たに追加しました。写真・絵画に20〜30%を推奨します。
- **ロゴ・漫画の再検証。** きれいな入力の検証の誤りを直して測り直しました。ロゴは JPEG 入力で拡大復元の探索値を使うようになり、漫画は JPEG 入力でのみ使います。
